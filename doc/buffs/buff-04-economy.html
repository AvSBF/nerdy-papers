Экономия

Квота — то, сколько бумажек нужно сдать в этом раунде — уменьшается на случайное число. Чем больше осталось до цели, тем выгоднее этот выбор.

buff_id: "quota_change_positive" бафф · зелёная весь раунд · стакается реализовано

Эффект

➖

quota_target минус случайное число (30–70), но не ниже total + 1

apply_buff("quota_change_positive") вычитает из quota_target случайное число от 30 до 70. Квота не может стать уже выполненной: минимум — total_deposited + 1. То есть 0/3 → 0/1, а при 250/300 резе — 250/251.

До выбораquota_target = 300например
После выбора300 − 30..70остаётся 230–270
Рез почти по цели250/300 → 250/251не выполнилась
Маленькая квота0/3 → 0/1не ниже total + 1

Схема работы

1. Выборapply_buff("quota_change_positive").
→
2. Резкаquota_target = maxi(total_deposited + 1, quota_target − randi_range(30, 70)).
→
3. UIdeposits_changed.emit — панель квоты обновляется.
Из Unity

Прямой аналог quotaTarget = Mathf.Max(totalDeposited + 1, quotaTarget - Random.Range(30, 70)). Никакой новой логики: всё остальное уже читает quota_target.

План внедрения

  1. Scripts/Round/round_controller.gd

    Резка квоты

    Одна ветка в apply_buff(). Ключевое — maxi(total_deposited + 1, …): квота после реза никогда не бывает уже выполненной. Раньше при 0/3 рез давал 0/−27, теперь — 0/1.

    round_controller.gd — экономия
    func apply_buff(buff_id: String):
	match buff_id:
		"quota_change_positive":
			var cut := randi_range(30, 70)
			quota_target = maxi(total_deposited + 1, quota_target - cut)
			deposits_changed.emit(total_deposited, buff_threshold)

Интерактив: квота тает

Жми «Выбрать бафф» — квота падает на случайное число. Собери бумажками.

интерактивквота против бумажек

Как проверить в игре

  1. Выбери «Экономию» — число в панели квоты должно прыгнуть вниз.
  2. Выбери ещё раз — снова уменьшится на случайное число.
  3. Проверь минимум: при квоте 0/3 рез должен дать 0/1.
  4. Проверь «невыполненность»: при 250/300 рез не должен завершить квоту — минимум 250/251.
