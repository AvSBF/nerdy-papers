Камера и обзор мышью

Классический mouse look: горизонталь вращает всё тело игрока, вертикаль — только камеру, а наклон ограничен, чтобы не переворачиваться. Вся логика — в одном маленьком файле.

Весь файл целиком

Scripts/Player/camera_rotator.gd
extends Camera3D

var pitch : float = 0.0

@onready var player : CharacterBody3D = get_parent()
@onready var controller : Node = player

func _unhandled_input(event: InputEvent) -> void:
	if Input.mouse_mode != Input.MOUSE_MODE_CAPTURED:
		return
	if event is InputEventMouseMotion:
		var motion : InputEventMouseMotion = event as InputEventMouseMotion

		player.rotate_y(-motion.relative.x * controller.mouse_sensitivity)

		pitch = clampf(
			pitch - motion.relative.y * controller.mouse_sensitivity,
			deg_to_rad(controller.min_pitch),
			deg_to_rad(controller.max_pitch)
		)
		rotation.x = pitch

1. Захват курсора

В player_controller.gd при старте курсор прячется и захватывается окном:

Scripts/Player/player_controller.gd
func _ready() -> void:
	Input.mouse_mode = Input.MOUSE_MODE_CAPTURED

func _unhandled_input(event: InputEvent) -> void:
	if event.is_action_pressed("ui_cancel"):
		if Input.mouse_mode == Input.MOUSE_MODE_CAPTURED:
			Input.mouse_mode = Input.MOUSE_MODE_VISIBLE
		else:
			Input.mouse_mode = Input.MOUSE_MODE_CAPTURED

MOUSE_MODE_CAPTURED — аналог Cursor.lockState = Locked. Esc (ui_cancel) переключает захват, чтобы можно было выйти из игры.

2. Ловим движение мыши

_unhandled_input вызывается для ввода, который не съел UI. Мы реагируем только на InputEventMouseMotion и только когда курсор захвачен.

motion.relative — это смещение мыши в пикселях с прошлого кадра. Именно оно используется, а не позиция курсора.

3. Yaw — поворот тела

фрагмент
player.rotate_y(-motion.relative.x * controller.mouse_sensitivity)

Вращаем родителя (Player), а не камеру. Тогда всё тело поворачивается вместе со взглядом — и движение, и точка удержания бумаги. Минус — потому что при движении мыши вправо картинка должна поворачиваться вправо, а в Godot положительный угол вокруг Y крутит против часовой.

4. Pitch — наклон камеры

pitch хранится отдельной переменной и ограничивается clampf между min_pitch и max_pitch (по умолчанию −80° и +80°). deg_to_rad переводит градусы в радианы, потому что rotation работает в радианах.

Почему хранить отдельно, а не читать rotation.x?

Если каждый кадр писать rotation.x = clampf(rotation.x + ..., ...), всё тоже будет работать. Но отдельная переменная — чище: значение не «застревает» на границе и его легко показать в отладке. Главное — применять её через rotation.x = pitch, а не копить ошибку.

Из Unity

В Unity ты бы делал transform.Rotate(Vector3.up, x) и transform.localEulerAngles с ручной нормализацией углов. В Godot rotate_y() и rotation.x уже принимают радианы и не требуют возни с «−180…180».

Интерактив: mouse look

Зажми кнопку мыши на картинке и води мышью. Слева — вид сбоку (наклон камеры), справа — вид сверху (поворот тела).
