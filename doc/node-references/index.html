Ссылки на узлы: как обращаться к нодам

В Unity ты привык к Find, FindWithTag, FindObjectOfType. В Godot это называется по-другому, но главное отличие в голове: у узла нет «ручки» — у тебя есть путь по дереву сцены и способы искать по дереву. Разберём все способы на реальном коде этого проекта.

Модель: путь, а не ссылка

Сцена — это дерево узлов. Чтобы «сослаться» на узел, ты либо знаешь его место в дереве (путь), либо ищешь его по каким-то признакам (имя, группа, тип). Первое — как transform.Find(), второе — как теги и FindObjectOfType.

Главный инстинкт из Unity

В Unity ты часто держишь ссылку в поле (public GameObject foo;). В Godot поле хранит путь к узлу или сам узел — но путь объявляется один раз в @onready, а дальше у тебя в руках узел, как привычная ссылка. Пути вычисляются при старте, а не каждый кадр.

Прямые пути

Если узел — твой потомок или известен путь от тебя, используй $Путь (сокращение get_node("Путь")). Поле объявляется через @onready: оно заполнится, когда узел войдёт в сцену и все дети будут готовы.

Scripts/UI/debug_menu.gd — путь по дереву
@onready var panel : PanelContainer = $Panel
@onready var spawn_count_slider : HSlider = $Panel/Margin/VBox/SpawnRow/SpawnCountSlider
@onready var spawn_count_value : Label = $Panel/Margin/VBox/SpawnRow/SpawnCountValue

Это как transform.Find("Panel/Margin/VBox/SpawnRow/SpawnCountSlider"), только путь отсчитывается от самого узла и указывается один раз в @onready. Внутри скрипта дальше работаешь с spawn_count_slider как с обычной ссылкой.

Соседи и родитель

Для соседей и родителей есть .. (родитель) и get_parent(). Так подсказка в UI находит игрока-соседа:

Scripts/UI/interaction_prompt.gd — соседний узел
@onready var interactor : Node = get_node("../Interactor")
Scripts/Player/player_movement.gd — родитель
@onready var player : CharacterBody3D = get_parent()

.. в пути — это родитель, как в файловой системе. Но не злоупотребляй: путь к «чужому» узлу ломается, если перенести узел. Для этого есть группы и autoload.

Группы = теги

Аналог тегов из Unity. Узел сам себя помечает в _ready(), а найти его можно в любом месте сцены. Именно так менеджер карточек находит все ящики, не зная их путей:

Scripts/Paper Storage/paper_storage.gd — помечаем себя
func _ready() -> void:
	add_to_group("paper_storage")   # как AddTag("paper_storage")
Scripts/UI/buff_card_manager.gd — находим всех
func _ready() -> void:
	process_mode = Node.PROCESS_MODE_ALWAYS
	overlay.visible = false
	for storage in get_tree().get_nodes_in_group("paper_storage"):
		storage.paper_deposited.connect(_on_paper_deposited)
paper_storage.gd — первый из группы (как FindWithTag)
var player := get_tree().get_first_node_in_group("player") as Node3D

Проверка «в какой я группе» — is_in_group("paper"), как в paper_storage.gd и player_interactor.gd. Группу можно назначить и в редакторе (поле «Groups» у узла), не только кодом.

Поиск по имени и типу

Когда не знаешь пути и нет группы — ищем по имени по всему дереву текущей сцены. Так делает дебаг-меню, когда ищет стол-раздатчик:

Scripts/UI/debug_menu.gd — поиск по имени
func _on_spawn_pressed() -> void:
	var creator := get_tree().current_scene.find_child("Paper Creator", true, false)
	if creator == null:
		return
	var amount := int(spawn_count_slider.value)
	for i in amount:
		creator.spawn_paper()

Три аргумента find_child(имя, recursive, owned): recursive = true — искать по всему дереву (как GameObject.Find), owned = false — не заглядывать в под-сцены чужих экземпляров.

Аналог FindObjectOfType

Если нужно «найти любой узел такого типа» — комбинируй: current_scene.find_children("*", "Paper", true, false) вернёт список, а as Paper или is Paper проверит тип. Но в Godot чаще используется группа, а не тип — так быстрее и надёжнее.

Важно: get_tree().current_scene — это корень текущей сцены (как корень сцены в Unity). Например, дебаг-меню лезет к игроку именно через него:

debug_menu.gd — absolute путь от корня сцены
@onready var interactor : Node = get_tree().current_scene.get_node("Player/Interactor")
# ...
var buff_ui := get_tree().current_scene.get_node("BuffCardUI") as Node
if buff_ui != null and buff_ui.has_method("force_show"):
	buff_ui.force_show()

class_name: свой тип

class_name даёт узлу имя типа — как класс в C#. После этого ты можешь типизировать переменные и делать as без сомнений:

Scripts/UI/buff_card.gd — объявление типа
class_name BuffCard
extends Button
buff_card_manager.gd — создание и типизация
var card := card_scene.instantiate() as BuffCard
cards_container.add_child(card)
card.setup(_random_buff(...))
card.pressed.connect(_on_card_pressed.bind(card))

class_name BuffCard — это одновременно и «мой тип», и имя, по которому Godot найдет скрипт. Как public class BuffCard : Button в Unity.

Уникальные имена %

Промежуточный вариант между путём и глобальным именем: пометь узел в инспекторе (правый клик → Access as Unique Name), и обращайся к нему из любого места сцены через %Имя:

Пример
@onready var crosshair : ColorRect = %Crosshair   # не зависит от пути в дереве

Путь неважен, главное — чтобы имя было уникальным в сцене. Это как «глобальная переменная на сцену».

Autoload: всегда активные сцены

Вопрос, который ты задал: «а если я сделаю так, чтобы UI-сцена была всегда активна через настройки проекта?» Отвечаю — это Autoload, синглтон на движке. Добавляется в project.godot (или в редакторе: Project → Project Settings → вкладка Autoload):

project.godot — секция autoload
[autoload]

HUD="*res://Prefabs/HUD.tscn"
GameState="*res://Scripts/Autoload/game_state.gd"

Звёздочка * — «включить» (можно отключить, убрав её). Что происходит: сцена/скрипт загружается до стартовой сцены, вешается на корень дерева (/root/HUD) и живёт, пока игра не закроется — даже когда текущая сцена меняется (как DontDestroyOnLoad).

Главное: из любой сцены, включая стартовую, ты обращаешься к нему по имени прямо — как к глобальной переменной. Никаких Find:

Из любой сцены, включая World.tscn
func _ready() -> void:
	# autoload-сцена: имя — это и есть ссылка на корневой узел
	HUD.show_message("Привет")
	HUD.get_node("ScoreLabel").text = "0"

	# autoload-скрипт: просто вызываешь методы
	GameState.add_score(10)
	print(GameState.score)

Под капотом HUD — обычный узел на /root, поэтому работают и пути: get_node("/root/HUD/ScoreLabel"). Но имя в [autoload] — это и есть зарегистрированная глобальная ссылка, ей и пользуйся.

Правило выбора

Свои дети и соседи — прямые пути $. «Чужие» объекты, которых может быть несколько (ящики, бумажки) — группы. Один глобальный сервис, который нужен везде и всегда (HUD, состояние игры, сохранения) — autoload. Поиск по имени find_child — последнее средство, оно медленнее и ломается при переименовании.
