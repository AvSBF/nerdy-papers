GDScript и сигналы

GDScript — это Python-подобный язык, встроенный в Godot. Он читается почти как псевдокод, но при этом типизируется. А сигналы заменяют C#-события и UnityEvent.

Синтаксис за 5 минут

Если ты писал на Python или C# — вот главные правила:

  • Вместо { } — отступы табами. Один блок = один уровень отступа.
  • Переменная: var speed := 5.0 (тип выведется) или var speed: float = 5.0.
  • Константа: const KILL_Y: float = -0.5.
  • Функция: func name(arg: Type) -> ReturnType:.
  • Нет new и нет ; в конце строк.
  • Комментарий — #.
Scripts/Paper/paper.gd (фрагмент)
class_name Paper
extends RigidBody3D

@export var paper_type : int = 1

signal picked_up(paper: Paper)

const KILL_Y : float = -0.5

@onready var type_label : Label3D = $TypeLabel

func get_paper_type() -> int :
	return paper_type
Из Unity

class_name Paper регистрирует глобальное имя класса — теперь Paper можно использовать как тип в других скриптах, как обычный класс C#. Без class_name скрипт всё равно работает, но на него нельзя ссылаться по имени.

@export и @onready

Две аннотации, которые ты будешь использовать постоянно.

@export

Показать в инспекторе

Прямой аналог [SerializeField] (и public-полей Unity). Значение задаётся в редакторе и видно в инспекторе.

@onready

Ссылка на узел

Переменная инициализируется прямо перед _ready(), когда дети уже существуют. Заменяет GetComponent и поиск в Start().

Scripts/Player/player_interactor.gd (фрагмент)
@export var interaction_distance : float = 3.0
@export var throw_speed : float = 5.0
@export_flags_3d_physics var interaction_mask : int = 0xFFFFFFFF

@onready var player : CharacterBody3D = get_parent()
@onready var camera : Camera3D = player.get_node("Camera3D")
@onready var hold_point : Node3D = camera.get_node("HoldPoint")

$TypeLabel — сокращение для get_node("TypeLabel"). Так берут дочерний узел по имени. Путь можно писать и глубже: $"Moving Part" (в кавычках, если есть пробел).

Scripts/Paper Creating Table/table_button_press.gd
@onready var moving_part : MeshInstance3D = $"Moving Part"
@onready var creator : Node3D = get_parent().get_node("Paper Creator")

Жизненный цикл узла

Запомни

Двигать CharacterBody3D нужно в _physics_process, а не в _process. Именно так сделано в player_movement.gd.

Сигналы

Сигнал — это встроенное в язык событие. Три действия: объявить, подключить обработчик и испустить.

Объявление и испускание — paper.gd
signal picked_up(paper: Paper)

# ... где-то внутри _integrate_forces:
_held = true
_flight_target = null
type_label.visible = show_label_while_held
picked_up.emit(self)
Подключение — player_interactor.gd
body.picked_up.connect(_on_paper_picked_up, CONNECT_ONE_SHOT)

# обработчик получает то, что передали в emit:
func _on_paper_picked_up(paper: Paper) -> void:
	if _flying_paper != paper:
		return
	_flying_paper = null
	held_papers.append(paper)

CONNECT_ONE_SHOT — как «одноразовая подписка»: обработчик отключится сам после первого срабатывания.

await: корутины по-годотовски

await приостанавливает функцию, пока не сработает сигнал или таймер. Это аналог yield return в C#.

Scripts/Paper Creating Table/table_button_press.gd
func interact():
	if _is_pressed:
		return
	_is_pressed = true

	moving_part.position.y = minimum_position
	creator.spawn_paper()
	await get_tree().create_timer(wait_time).timeout

	moving_part.position.y = initial_position
	_is_pressed = false
