Взаимодействие: группы, рейкаст, рука

Как игра понимает, на что ты смотришь? Рейкаст из камеры + группы узлов. Здесь встречаются сразу несколько важных механик Godot: статические утилиты, физический запрос и кастомные сигналы.

Утилита рейкаста

В проекте есть отдельный класс InteractionRaycast. Он не узел, а просто набор статических функций — удобно вызывать из любого места.

Scripts/Utilities/interaction_raycast.gd
class_name InteractionRaycast
extends RefCounted

static func ray_forward(camera: Camera3D, distance: float, mask: int = 0xFFFFFFFF) -> Dictionary:
	var space := camera.get_world_3d().direct_space_state
	var from := camera.global_position
	var to := from + camera.global_transform.basis * Vector3(0, 0, -1) * distance
	var query := PhysicsRayQueryParameters3D.create(from, to, mask)
	query.collide_with_areas = true
	query.collide_with_bodies = true
	return space.intersect_ray(query)

static func get_node_in_front(camera: Camera3D, distance: float, predicate: Callable, mask: int = 0xFFFFFFFF) -> Node:
	var hit := ray_forward(camera, distance, mask)
	if hit.is_empty():
		return null
	var collider := hit["collider"] as Node
	while collider != null:
		if predicate.call(collider):
			return collider
		collider = collider.get_parent()
	return null
Из Unity

Это аналог Physics.Raycast, только результат приходит словарём (Dictionary) с ключами collider, position, normal и т.д. Если ничего не попали — словарь пустой, hit.is_empty() вернёт true.

Зачем подниматься по родителям?

Луч попадает в коллайдер — обычно это дочерний CollisionShape3D. Но нужен-то нам логический узел, который в группе. Поэтому цикл while поднимается от коллайдера вверх по дереву, пока не найдёт подходящий узел.

Interactor: мозг взаимодействия

Ключевые части player_interactor.gd:

Scripts/Player/player_interactor.gd (фрагмент)
signal target_changed(target: Node)
signal held_paper_changed(paper: Node)

const GROUPS : Array[String] = ["button", "paper"]

@export var interaction_distance : float = 3.0
@export_flags_3d_physics var interaction_mask : int = 0xFFFFFFFF

func _physics_process(_delta: float) -> void:
	_update_target()

func _find_target() -> Node:
	return InteractionRaycast.get_node_in_front(
		camera,
		interaction_distance,
		func(node : Node) -> bool:
			for group in GROUPS:
				if node.is_in_group(group):
					return true
			return false,
		interaction_mask
	)

func(node) -> bool: — это лямбда, аналог делегата Func<Node, bool> в C#. Она передаётся как Callable.

Почему цель обновляется в _physics_process?

Рейкаст — часть физического мира, и его корректнее делать на физическом шаге. Кроме того, _update_target испускает target_changed только когда цель реально изменилась — чтобы не дёргать UI каждый кадр.

фрагмент
func _update_target() -> void:
	var target := _find_target()
	if target == current_target:
		return
	current_target = target
	target_changed.emit(current_target)

func _unhandled_input(event: InputEvent) -> void:
	if event.is_action_pressed("interact"):
		interact_with_current()
	elif event.is_action_pressed("throw"):
		_throw_current()

Подсказки в UI

Интерфейс ничего не «опрашивает» — он просто слушает сигналы Interactor:

Scripts/UI/interaction_prompt.gd
func _ready() -> void:
	interactor.target_changed.connect(_update_prompt)
	interactor.held_paper_changed.connect(_update_prompt)
	label.hide()

func _update_prompt(_arg: Variant = null) -> void:
	if not interactor.held_papers.is_empty():
		label.text = "[G] to throw"
		label.show()
		return
	var target : Node = interactor.current_target
	if target != null and target.is_in_group("button"):
		label.text = "[E] to interact"
		label.show()
	elif target != null and target.is_in_group("paper"):
		label.text = "[E] to pick up"
		label.show()
	else:
		label.hide()
Паттерн

«Логика испускает сигнал → UI подписывается и обновляется» — это стандартный способ развязывать логику и интерфейс в Godot. Никаких FindObjectOfType<UI>().
