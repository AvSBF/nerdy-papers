Мышление Godot

Прежде чем писать код, надо перестроить пару привычек. Unity и Godot решают одни и те же задачи, но «изнутри» устроены по-разному. Эта глава — про то, что именно поменять в голове.

Сцена — это дерево узлов

В Unity сцена — это список GameObjects, у каждого из которых есть Transform и набор компонентов. В Godot сцена — это дерево узлов (Node), и каждый узел делает что-то конкретное. Дерево определяет, кто кого двигает, кто наследует трансформацию и в каком порядке всё обновляется.

Из Unity

MeshInstance3D — это аналог MeshRenderer, CollisionShape3D — аналог Collider, а «скрипт на узле» — это как MonoBehaviour, только привязанный к конкретному узлу, а не к отдельному GameObject.

Узлы вместо компонентов

В Unity ты берёшь пустой GameObject и навешиваешь компоненты. В Godot ты выбираешь готовый тип узла. Узел уже умеет то, что тебе нужно, а поведение добавляется скриптом.

CharacterBody3D

Кинематический персонаж

Аналог CharacterController. Ты сам считаешь velocity и вызываешь move_and_slide().

RigidBody3D

Физическое тело

Аналог Rigidbody. Движением управляет физический движок, а не ты.

Area3D

Зона-триггер

Аналог Collider с Is Trigger. Ловит вход/выход объектов сигналами.

Camera3D

Камера

Аналог Camera. Активная камера рендерит вид.

CanvasLayer

Слой интерфейса

Аналог Canvas в Screen Space — Overlay. UI не крутится вместе с 3D-миром.

Label3D

Текст в мире

Текст, висящий прямо в 3D. В Unity пришлось бы возиться с TextMeshPro.

Сцены = префабы

В Godot нет отдельной сущности «префаб». Любая сцена (.tscn) может быть вставлена в другую сцену — как экземпляр. Это и есть префаб.

В проекте есть такие переиспользуемые сцены:

  • Prefabs/Player.tscn — игрок
  • Prefabs/paper.tscn — одна бумажка
  • Prefabs/paper_creating_table.tscn — стол-раздатчик
  • Prefabs/paper_storage.tscn — ящик для хранения
  • Prefabs/+1_label.tscn — всплывающая надпись «+1»

Главная сцена Scenes/World.tscn — это сцена, которая собирает их вместе: пол, игрок, стол, четыре ящика и меню отладки.

Важно

В Godot слово instance означает «экземпляр сцены, вставленный в другую сцену». А instantiate() в коде — это создание копии сцены во время игры. Не путай эти два «инстанса».

Скрипт живёт на узле

Скрипт начинается с extends — он как бы «продолжает» тип узла. Поэтому в нём сразу доступны position, velocity, сигналы и методы этого узла.

Сравни: слева привычный MonoBehaviour, справа — GDScript из проекта.

Unity C# — Player.cs
using UnityEngine;

public class Player : MonoBehaviour
{
    public float moveSpeed = 5f;

    void Start()
    {
        Cursor.lockState = CursorLockMode.Locked;
    }

    void Update()
    {
        // ...
    }
}
Scripts/Player/player_controller.gd
extends CharacterBody3D

@export var move_speed : float = 5.0

func _ready() -> void:
	Input.mouse_mode = Input.MOUSE_MODE_CAPTURED

Заметь: нет класса Player и нет GetComponent. Тип узла — это и есть класс, а extends CharacterBody3D даёт доступ к его API напрямую.
